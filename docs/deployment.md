# Deployment (Cloudflare Pages)

Decision O1 (Hamza, 2026-11-22): the site is hosted on **Cloudflare Pages**, built from the GitHub repository. The custom domain is a separate, later decision.

## What the repository already provides

- `npm run build` writes the static site to `dist/`. It runs `check:content` first; with `CONTENT_STRICT=1` any unverified content fails the build.
- Content Security Policy: a `<meta>` tag on every page, generated by Astro (`security.csp` in `astro.config.mjs`) with hashes of the inline scripts and styles. `connect-src 'none'`: the site never makes a network request.
- `public/_headers`: other security headers (`frame-ancestors`, `nosniff`, referrer and permissions policies) and long caching for hashed assets. Cloudflare Pages reads this file from `dist/`.
- `content/legal.json`: host details for the legal notice. A build with `SITE_URL` set fails if they are missing.

## One-time setup (Hamza, in the Cloudflare dashboard)

1. Create a Cloudflare account.
2. Create a Pages project and connect it to GitHub. Give Cloudflare access to **this repository only**.
3. Build settings:
   - build command: `npm run build`
   - build output directory: `dist`
   - production branch: `main`
4. Environment variables:
   - Production: `SITE_URL` = the public URL (the `*.pages.dev` address until a domain is chosen), `CONTENT_STRICT` = `1`, `NODE_VERSION` = the version in `.nvmrc`.
   - Preview: `NODE_VERSION` only. Previews have no `SITE_URL`, so they carry no canonical links.
5. **Leave Cloudflare Web Analytics and any other tracking off.** The site promises no analytics (decision D5, legal page).

Every PR then gets a preview URL; every merge to `main` deploys production.

## After the first deployment

- Check the live headers: the response must include the headers from `public/_headers`.
- Check the social preview with the production URL (`og:image` needs `SITE_URL`).
- Run Lighthouse on the live URL once.
